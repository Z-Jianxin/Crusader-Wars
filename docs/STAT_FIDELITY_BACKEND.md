# Attila stat variant backend

The backend creates private Attila database records for the profiles accepted by the CK3 exporter and mapper. It changes base normal/AP weapon damage and effective infantry or ordinary cavalry hit points before Attila starts. It does not use unverified Warhammer Lua stat APIs, modify existing game packs, or promise deterministic combat outcomes.

## Entry points

`CrusaderWars.StatFidelity.UnitStatProfile` contains an evidence identity, mapped base unit key, damage multiplier and hit-point multiplier. `StatFidelityBackend.GeneratedKey(profile)` produces the same stable `cc_sf_` key that `Generate(...)` writes. The mapper registers profiles while producing battle XML; `PackFileCreator` materializes their records before packing. Profile conflicts, non-finite/non-positive factors, integer overflow and unresolved dependencies abort the new battle. Factors are never silently capped by this backend. Integer fields round to the nearest integer, halfway away from zero; fewer than one resulting hit point is rejected.

Sources: [profile/key](../CrusaderWars/packfile/stat_fidelity/UnitStatProfile.cs), [backend](../CrusaderWars/packfile/stat_fidelity/StatFidelityBackend.cs), [variant builder](../CrusaderWars/packfile/stat_fidelity/StatVariantBuilder.cs), [pack publication](../CrusaderWars/packfile/PackFile.cs).

`StatFidelityBackend.Prepare(runtimeRoot, attilaExecutable, cacheRoot = null)` returns a [PreparedAttilaDatabase](../CrusaderWars/packfile/stat_fidelity/PreparedAttilaDatabase.cs) shared by planning and later generation. `Query(unitKey)` supplies actual merged base melee normal/AP damage, nominal soldiers, entity/bonus/mount HP, category, attack/defence/charge, and mounted/special/missile/naval flags. `EffectiveInfantryHitPoints` remains null for mounted/special/naval units. `EffectiveHitPoints` includes man + land bonus + mount for supported ordinary cavalry, and is null for unsupported special/naval types. These are base database values, not measured DPS or post-effect combat totals. `AssertFresh()` checks source pack paths/order/lengths/timestamps; `Generate(profiles, battleRoot)` validates freshness again, applies battle-local names to a private database copy, and emits profiles using the same prepared source. The pack publisher reuses a prepared session database when present. The optional cache path supports isolated replay using an already completed cache.

Representation counts belong to individual generated formations: one quality profile may be reused across multiple split formations. `NominalSoldiers` is a source DB value. The native count probe actually spawned 20 and 500 soldiers of the same generated unit whose nominal DB count is 160, as recorded by native `number_of_men_alive()` calls. This verifies the tested XML overrides; it does not imply arbitrary unlimited counts or exact combat-budget equivalence.

## Active database

The source resolver includes PFH4 boot/release/patch packs, explicitly enabled packs from `used_mods_cc.txt` in reverse file order, and automatic movie packs. Crusader Conflicts lists its highest-priority mod first. The old generated `CrusaderConflicts.pack` and temporary build packs are excluded. Missing or ambiguous enabled pack names fail rather than selecting an arbitrary copy.

Localization follows `data/language.txt` (Attila's two-letter codes), with `local_en_shared_rome2.pack` below the selected locale as a fallback. If the file is absent, a single installed locale can be inferred; several installed locales cause an explicit error. Other language packs are excluded. Per-battle localization prepared by Crusader Conflicts is applied last.

Pack-file priority is resolved **before database rows**. Higher-priority packs replace entire files at the same virtual path. A row omitted by a replacement file must not survive from the overwritten file. Remaining fragments are processed in source priority order and descending filename order so earlier fragments win within a source. TSV column order and schema versions are preserved, and incompatible definitions fail explicitly.

RPFM 3.99 can emit unquoted carriage returns in localization TSV text. The installed Age of Justinian supply-description table demonstrated this: parsing the export as ordinary TSV split a valid description into two short rows and aborted generation. If a localization TSV fails validation, the backend re-extracts its original binary LOC file and decodes that fixed format losslessly, then writes properly quoted TSV. It never guesses how to join malformed text fragments or drops unrelated rows. The [decoder](../CrusaderWars/packfile/stat_fidelity/LocBinaryReader.cs) follows RPFM's documented [LOC structure](https://github.com/Frodo45127/rpfm/blob/master/rpfm_lib/src/files/loc/mod.rs), validates header/version/lengths/booleans, and preserves CR/LF, tabs, quotes and Unicode.

The whole-file behavior follows RPFM's own [pack merge implementation](https://github.com/Frodo45127/rpfm/blob/master/rpfm_lib/src/files/pack/mod.rs): `read_and_merge` groups packs by type, reverses their priority, and extends the virtual-path map with each pack's files. Its [dependency implementation](https://github.com/Frodo45127/rpfm/blob/master/rpfm_extensions/src/dependencies/mod.rs) also explicitly replaces vanilla files with parent files. [Attila game metadata](https://github.com/Frodo45127/rpfm/blob/master/rpfm_lib/src/games/supported_games.rs) includes Boot and the language-specific packs. This is tool-source evidence; duplicate-fragment priority still needs an in-game Attila fixture with deliberately conflicting rows to establish engine behavior independently.

## Generated records

Each profile gets unique `main_units` and `land_units` keys. Melee weapons are cloned and both `damage` and `ap_damage` are scaled. Missile weapons, their default projectile, and every alternate-ammunition junction/projectile are cloned. Artillery engine missile chains are supported by the table builder, although the CK3 mapper can reject siege profiles when CK3 siege progress cannot justify field damage.

For ordinary infantry, effective HP is `battle_entities.hit_points + land_units.bonus_hit_points`. For non-neutral HP factors, the backend assigns the scaled total to a private man entity and zeroes the cloned unit's bonus HP. This supports reductions without negative bonus HP. A factor of exactly one preserves the entity and bonus HP fields separately, avoiding unverified redistribution on mounted units. It preserves attack/defence, armour, shields, animation, movement, formations, abilities, shared variant assets, card images and localized names. Visual variants resolve through the land-unit key, as required by Attila's foreign key, even when an overhaul's recruitment-unit key differs. Existing weapon contact effects, projectile explosions and scripted/synchronized kills are retained rather than reinterpreted as CK3 damage; those mechanics can change effective lethality independently of the scaled damage fields.

Ordinary one-rider cavalry is supported after native card and combat validation established effective HP as `man + bonus + mount`. Non-neutral HP changes clone both the mount record and its entity privately. For multiplier `k`, compute `dismounted = round((man + bonus) * k)` and `mounted = round((man + bonus + mount) * k)`; emit `man' = round(man * k)`, `bonus' = dismounted - man'`, and `mount' = mounted - dismounted`. This preserves the rounded total exactly in both states and the component proportions within integer rounding. Identity multipliers preserve all original components and the mount reference exactly. The tested mounted pilot had card totals 232/322/357/447 for native/rider-only/mount-only/both-entity treatments and directional combat response. Its land bonus was deliberately fixed to identify the formula; production scales that bonus too. Dismounted combat itself has not been measured.

Chariot, animal, engine, articulated and nonstandard multi-rider mounted HP changes still fail explicitly. Damage-only profiles can retain their original HP. Naval profiles are rejected. Supporting ordinary cavalry does not establish special-entity behavior or exact CK3-to-Attila combat equivalence.

The builder resolves every record it needs to change, plus the base visual rows, localization and ability junctions. Unchanged referenced assets remain provided by the active mods; this is not a full missing-mesh/animation/asset validator.

## Cache and publication

Cache buckets include source path, size, timestamp, schema SHA-256 and cache-format version. Version `v3-mounted-hp` adds mount records. A matching completed v2 cache can seed a new v3 attempt while only the added mounts are extracted; the old evidence remains untouched. Every extraction uses a new `attempt-<guid>` directory. A completion marker selects only a fully decoded attempt. Incomplete attempts are never recursively deleted. Cache root/bucket/attempt directories, markers and descendants reject links/reparse points. Old failed attempts can be inspected or removed manually after the application has stopped.

Generated tables are published only after all profiles validate. RPFM commands use structured argument lists, drain stdout/stderr concurrently, enforce a timeout and check exit codes. A fresh pack is built beside the destination, verified readable, and atomically replaces the previous pack. A backend failure leaves the existing production pack unchanged and records the diagnostic in the coverage report.

## Validation

Run the focused project with a .NET 9 SDK:

```powershell
dotnet restore Tests/StatFidelity.Backend.Tests/StatFidelity.Backend.Tests.csproj --source https://api.nuget.org/v3/index.json
dotnet test Tests/StatFidelity.Backend.Tests/StatFidelity.Backend.Tests.csproj --no-restore
```

The [tests](../Tests/StatFidelity.Backend.Tests/BackendTests.cs) cover independent opposing profiles, damage/AP and alternate ammunition, effective infantry HP, ordinary mounted/dismounted HP sums and neutral preservation, special-entity rejection, abilities/visuals/names, row priority and whole-file replacement, schema rejection, missing-reference publication failure, bounds, TSV quoting, load-order directories and Boot/localization selection.

To enable the real pack roundtrip test, set `CC_RPFM`, `CC_SCHEMA`, and `CC_TEST_PACK` to a compatible RPFM CLI, Attila schema and an installed overhaul pack. It finds a self-contained eligible infantry row, clones it, builds a scratch pack, extracts it again and checks the resulting records. It also verifies that an interrupted-cache marker causes a fresh attempt without deleting the previous attempt. This test has been run with RPFM 3.99.109 and the residual AD919 compatibility pack; no production pack is changed.

Set `CC_TEST_LOC_PACK` to the installed `age_of_justinian555_2.0_BETA.pack` to run the real multiline-localization regression alongside those checks. With both installed-pack tests enabled, all 16 backend tests passed on 2026-10-21, including composite mounted queries, exact rounding at factors 2/0.5/1.3, stale-context rejection and isolation of per-battle name overlays.

On 2026-10-21 the offline battle harness also completed database generation from the actual `snapshot-3` CK3 handoff through the installed Early Medieval 919 mapper and full active Attila pack stack. All eight required mod files were present, including the AD919 compatibility pack, four Age of Justinian parts and the Mubarizun submod. It generated 15 accepted profiles. A task-owned 54,102,318-byte battle pack was built without installing it; all nine generated stat/localization tables, 112 rows and every field matched after binary roundtrip. Evidence is in the session's `harness-combat02-database-v2` output (`result.json` and `pack-roundtrip-result.json`). A pre-existing runtime UI localization file could not export as TSV and remained binary; this does not affect the successful comparison of generated tables. This is offline conversion/pack evidence, not a gameplay result for that full mod stack.

RPFM success proves binary/schema compatibility, not engine combat behavior. Attila build 25370302 has now completed infantry and mounted treatment pilots: actual cards and native casualty logs confirm private variant stats and directional combat effects. The task-only [calibration harness](../Tests/AttilaCalibration/README.md) documents those observations, excluded idle lanes, noisy controls and count probes.

The subsequent active-stack probe loaded/rendered with all eight real asset mods. The root inspected the actual mapped knight card at **43/43 soldiers, XP0, melee damage 247 and AP damage 99** (AP is part of the 247 total), with no missile weapon. This validates the mapped mounted formation and damage in the overhaul. Its health row is hidden by the overhaul UI: active Catafractarii 210→420 HP and knight 151 HP remain verified query/emission/binary values, **not full-stack live-card health observations**. The ordinary-cavalry HP formula is supported separately by the completed vanilla component-card/combat tests. Remaining work includes full-stack HP/ability observation, alternate missiles, deliberately conflicting pack/fragment tests, dismounted combat and fitting cross-game response factors. No exact DPS or CK3 battle-outcome equivalence is claimed.

Calibration time fields are controller callback counters, not a verified simulation clock. The native Lua timer wrapper does not establish its speed/pause coupling; record wall timestamps and observed native speed separately. Pilot cutoff 300 and `median_seconds` must not be interpreted as calibrated simulation-time or DPS measurements.
